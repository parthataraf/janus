# Exact pins, deliberately. A fresh `pip install` on a clean server resolves
# ">=" to whatever is newest that day, so the image you build in a month is not
# the image you tested. That drift cost a deploy: `mcp>=1.28.1` pulled 2.0.0,
# which renamed McpError -> MCPError and streamablehttp_client ->
# streamable_http_client and swapped httpx for httpx2. Bump these on purpose,
# with a test run — never by accident.
#
# Caveat: this pins DIRECT deps only. Transitive versions (torch, transformers,
# numpy, pydantic) still float within their parents' ranges. torch is pinned
# separately in Dockerfile.api because it is installed from the CPU-only index.

# Phase 1 (retrieval core + smoke test)
python-dotenv==1.0.0
psycopg[binary]==3.3.4
sentence-transformers==5.6.0   # cross-encoder reranker

# Phase 2 generation / Phase 3 API
openai==1.109.1                # OpenRouter-compatible client (generation + embeddings)
fastapi==0.139.0
uvicorn[standard]==0.51.0

# Phase 4 LoL ingestion: Data Dragon fetches (also an openai dep)
httpx==0.28.1

# Phase 4h live stats: OP.GG official MCP client (live matchup/win-rate path).
# HARD PIN — do not relax to >=. mcp 2.x is a breaking major: the two symbols
# core/opgg_live.py imports were both renamed with no back-compat alias, and it
# depends on httpx2, a different HTTP stack from the one openai uses. Moving to
# 2.x is a migration, not a version bump.
mcp==1.28.1

# Dev/test
pytest==9.1.1
